## 실행 및 관찰

audit_claude_followup.py를 실제 실행했다. 운영 데이터는 PostgreSQL의 REPEATABLE READ / READ ONLY 트랜잭션으로 읽었다. 오래된 SQLite 파일을 최신 운영 결과로 사용하지 않았다. 산출물은 현재 AI System/handoff 아래에만 저장했다.

- 최근 sector_focus 실행 48개를 보존했다. 원장 현금흐름을 재구성한 수익률이 저장된 소수 둘째 자리 수익률과 모두 일치했다(허용 차이 0.0051%p).
- 매도 수량 초과, 음수 현금, 구간 외 거래, 미청산 수량, 에코프로(086520) 거래는 이 검사 범위에서 발견하지 않았다.
- 구간별 거래 종목은 16~38개다. 이는 기간 전체 종목 수이며 동시 분산이나 위험 기여의 균등함을 증명하지 않는다.
- 저장 순서와 실행 스크립트 호출 순서로 추정한 두 묶음에서 대응하는 24쌍 거래 JSON 해시가 모두 같다. 별도 프로세스/세션에서 독립 재실행됐다는 증거는 부족하다.
- 6개 구간의 날짜는 비중복이다. 하지만 스크립트에는 과거 학습·검증 창별 후보 선택과 동결 이력이 없다. 따라서 이를 사전 등록된 walk-forward OOS 통과로 인정하지 않는다.
- 모든 48개 실행에서 partial_tp_pct, cost_multiplier, exclude_codes가 parameter_json에 없다. run_hash 하나에 서로 다른 거래 결과가 묶이는 사례가 13개 그룹이다.
- 예: run_hash 5372af1eaa07에 114.69%, 117.77%, 119.29%, 121.28%가 함께 연결된다. 변형 조건을 해시로 식별할 수 없다.
- 48개 모두 created_at, equity_json, max_drawdown_pct가 비어 있다. 백테스트 원장에 기록된 순손익을 검산했으며, 체결 가격·세금·슬리피지를 원천 시세로 독립 재산정한 것은 아니다.

## 수익 숫자 재해석

아래 조건 이름은 인계 문서와 호출 순서의 대응 가설이다. 실행 계약에 해당 파라미터가 누락되어 확정 식별로 취급하지 않는다.

| 조건 | 6구간 평균 수익률 | 구간별 수익률의 가정상 복리 곱 |
|---|---:|---:|
| 기준선 1x 비용 | 45.4483% | 655.68% |
| 부분익절 1x 비용 | 46.1550% | 659.84% |
| 기준선 2x 비용 | 43.4283% | 593.74% |
| 부분익절 2x 비용 | 44.5983% | 610.19% |

평균 개선폭 +0.7067%p / +1.17%p는 인계 수치와 일치한다. 개선은 1x에서 3/6구간, 2x에서 4/6구간이다. 약한 앞 구간을 제외하면 평가기간 사후선택이 된다.

복리 곱은 단순 산술 참고다. 엔진은 구간마다 9천만원과 종목당 1천만원 티켓으로 다시 시작한다. 현금 승계·티켓 재조정·유동성 변화가 없는 계산을 실제 누적 운용 성과로 제시하면 안 된다. 이 가정상 수치조차 800%보다 작다. 후보 미채택을 유지한다.

## 다음 실행 계획과 5단계 인계 지시

최신 통합 인계의 역할 분담을 따른다. 이전 PLAN_AND_EVIDENCE.md에서 Qwen에게 코드 작성 역할을 준 부분은 아래 지시로 대체한다. Qwen은 단순 전처리에 한정한다.

| 단계 | 지시 | 현재 증거 / 다음 단계 진입 기준 |
|---|---|---|
| 1 GPT/Codex 계획 | 기간·자본·시장·MDD·레버리지·비용·OOS 창·후보 탐색 예산을 동결. 매수/매도와 동시 종목·섹터 한도, 포지션 경계 승계 규칙까지 명시. | 평가 계약 초안과 이번 DB 대조 확보. 사용자 조건과 위험 한도 미확정. |
| 2 Gemini 외부 보강 | 당시 비용 원출처와 시점별 투자대상 자료를 조사하고 PIT·종목 편중 반례를 제출. 채택/기각 사유를 계약에 연결. | 기존 문헌 입력은 있으나 Gemini 실제 검수 응답 미확인. 출처·응답 ID·동결 spec hash 필요. |
| 3 Qwen + DeepSeek | Qwen은 원장 필드 추출·중복 확인·구간 정렬만 수행. DeepSeek는 그 결과를 검사하고 Claude 검토용 결함 목록 작성. 코드 변경·성과 생성·종결 권한 없음. | Qwen 명의 문서와 실제 숫자는 대조됨. DeepSeek 실제 응답 미확인. 코드/실측은 실제 실행기가 수행하고 run/session/data/spec 지문을 남겨야 함. |
| 4 Claude 독립 검토 | 수정 요청을 해소했는지 같은 불변 증거로 재검토. 실행 파라미터 지문, 일별 MDD, OOS 선택 이력, 복수 실행을 직접 확인. | NEEDS_REVISION 문서 확보. 실제 세션·응답 지문 및 새 검토 필요. |
| 5 GPT/Codex 최종 검수 | 모든 기계 검사와 단계 증거가 갖춰졌는지 검수. 누락이 있으면 제출 반려. 자기 보고로 목표 종결하지 않음. | 이번 48개 원장 검산·24쌍 비교·13개 해시 충돌 증거 누적. 최종 승인 아님. |

다음 구현 과업은 실행 계약 누락을 수정하고 일별 자산·실행 출처를 보존하는 것이다. 단위 수락 기준은 부분익절/비용/제외종목 변경 시 spec hash가 반드시 달라지고 동일 입력은 동일 지문을 내며, 각 run에 UTC 시각과 일별 자산을 남기는 회귀검사다. 기존 원장을 소급해 새 계약으로 덮어쓰지 않는다. 이후 동결된 계약으로 새 독립 실행 두 회와 비중복 OOS를 수행한다.

800% 후보 제출 기준은 순자산 9배 이상, 사용자 MDD 한도 이내, 실제 비용과 자본 승계 반영, 사전 동결 OOS 및 독립 재현, 5단계 증거 충족이다. 계약 미확정·표본 재사용·파라미터 추적 불능·일별 자산 부재가 남으면 통과시키지 않는다. 앞서 발견한 목표 레지스트리 종결 게이트 결함도 아직 수정되지 않았다.
