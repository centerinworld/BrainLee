# Claude 차단 진단 정정 및 사용자 승인 원칙

사용자 지시: "나는 내 승인이 있으면 에이전틱 에이아이가 실행 되었으면 좋겠어."

원본 세션 e7b866af-4935-4d2b-bddc-d212ade3bb23, 2026-09-14T11:54:27.795Z의 Bash tool_result를 확인했다. 메시지는 Claude Code auto mode classifier가 Create Unsafe Agents 사유로 명령을 거부했다고 명시한다. 일반 모델 정책상 절대 실행 불가라고 판정할 근거가 아니다. Codex가 앞서 영구적으로 패치 전용 구현으로 축소한 것은 사용자 요구를 충족하지 못했다.

차단 명령은 여러 CLAUDE 세션 환경변수를 env -u로 제거한 뒤 workspace-write Codex 워커를 호출했다. 이 환경변수 제거가 차단 원인이라고 확정할 수는 없다. 해당 명령은 이번 조사에서 재실행하지 않았다.

공식 문서 https://code.claude.com/docs/en/permission-modes 는 자동 분류기가 거부한 작업을 /permissions의 Recently denied에서 수동 승인으로 재검토하는 절차를 설명한다. 이 절차는 해당 제품의 사용자 승인 UI가 담당한다. Codex가 사용자의 승인 버튼을 대신 누르거나 승인 기록을 만들어서는 안 된다. 보호장치 비활성화, 광범위 Bash 허용, 세션 표시 제거로 차단을 피해 실행하는 경로를 만들지 않는다.

원하는 구현 계약:
1. 사용자에게 구체적인 작업, 대상 저장소와 기준 커밋, 쓰기 범위, 명령, 실행/비용 한도를 제시한다.
2. 정식 사용자 승인 경로에서 그 작업에 대한 승인을 받는다.
3. 승인된 범위 안에서 실제 에이전트가 격리 환경에서 수정·테스트한다. 범위 확대나 새 차단은 별도 처리한다.
4. 변경 전체와 테스트 결과를 검토한다. 운영 반영은 사용자에게 승인된 범위에 따라 처리하며 작업 실행 승인을 자동으로 운영 배포 승인으로 확대하지 않는다.
5. 실패/시간 초과/차단은 중단 상태로 보존하고 완료로 승격하지 않는다.

현재 상태: 원인 진단을 정정하고 사용자 요구를 기록했다. Claude 권한 설정은 변경하지 않았고 자율 워커도 아직 복원하지 않았다. 기존 patch worker는 이 계약의 승인형 에이전트 실행 구현을 대신하지 못한다.
