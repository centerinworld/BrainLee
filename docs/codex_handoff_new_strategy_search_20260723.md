### 13.2 확인된 원인

`portfolio_engine.CashPortfolio` 자체의 동적 티켓 확장 계약은 맞다.

- `position_limit = floor(marked_equity / ticket_budget)`
- 즉 1억원이 1.1억원이 되면 10개 티켓에서 11개 티켓로 확장되는 구조.

문제는 `merged_simulator.simulate_merged_account`가 `mark_prices`를 충분히 갱신하지 않는 데 있다.

현재 코드 흐름:

```python
dates = sorted({order.date for order in normalized})
for day in dates:
    day_orders = [order for order in normalized if order.date == day]
    for order in day_orders:
        marks[order.stock_code] = order.price
    ...
    portfolio.buy(..., mark_prices=marks)
```

따라서:

- 시뮬레이터 날짜 축이 “거래일 전체”가 아니라 “주문이 있는 날”뿐이다.
- 보유 중인 종목이 몇 달 동안 주문 스트림에 다시 등장하지 않으면 평가가격이 오래된 체결/신호 가격으로 남는다.
- 동적 티켓 확장 판단이 실제 계좌 평가액이 아니라 “부분적으로 갱신된 주문가격 맵”에 의존한다.
- 최종 평가도 전체 보유종목의 최신 종가가 아니라 마지막 주문가격 또는 오래된 마크 가격에 의존할 수 있다.

### 13.3 왜 체결 수까지 달라지는가

일별 마킹 엔진은 모든 거래일의 보유종목 가격을 갱신하므로, 미실현 손익이 동적 티켓 수에 반영된다.

그 결과:

- 기존 엔진보다 매수체결이 259건 늘어났다.
- 이는 단순 평가액 표시 차이가 아니라 실제 포트폴리오 경로가 달라진다는 뜻이다.
- 따라서 `+628.71%`와 같은 기존 병합조합 결과는 “주문 스트림 가격 기반 근사”이지, 완전한 1억원 복리 계좌 시뮬레이션으로 보기 어렵다.

### 13.4 현재 결론

- 새 전략/필터를 더 찾기 전에 병합 시뮬레이터를 표준화해야 한다.
- 현재 전략센터에 표시되는 병합조합 수익률은 `execution_strict`처럼 보이더라도, 동적 티켓 확장 관점에서는 아직 `daily_marking_incomplete` 리스크가 있다.
- `conservative_v10_bear_gate` 자체가 무효라는 뜻은 아니다. 다만 표시 수익률과 체결 원장은 일별 마킹 기준으로 재산출해야 한다.

### 13.5 클로드/후속 작업 지시

1. `merged_simulator.simulate_merged_account`에 선택형 daily price provider를 추가한다.
   - 주문 날짜뿐 아니라 전체 거래일 또는 최소 모든 주문일 직전까지 보유종목 최신 종가를 마킹.
   - `price_history` 기준, 실행 가격은 기존 주문 가격 유지.

2. `MergeConfig`에 명시적 필드를 추가한다.
   - 예: `marking_mode="order_stream" | "daily_close"`
   - 기존 결과는 `order_stream`로 보존하고, 전략센터 실전 표준은 `daily_close`로 전환.

3. `run_registry`/프론트 검증 배지를 분리한다.
   - `execution_strict`만으로는 부족.
   - `daily_marking_verified` 또는 `order_stream_marking` 표시 필요.

4. 기존 선택 조합을 전부 재산출한다.
   - `core_sector_trail`
   - `conservative_v10_bear_gate`
   - `combo_605`, `combo_539`, `combo_510`, `combo_474`, `combo_546`

5. 일별 마킹 기준으로 다시 홀드아웃을 실행한 뒤에만 새 로직 탐색을 재개한다.
