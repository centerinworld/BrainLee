# Stock System 개선 상세 구축 계획

작성: 2026-10-10 KST · 최종 정합 점검: 2026-10-11 KST · 작성자: Codex · 상태: **정본 계획 v1.1 / P0 통제 재정렬 중**

이효준 owner의 투자 원칙을 중심으로 **자료 수집 → 변화 감지 → 기업 연구 → 전략 검증 → 비중 결정 → 실행 → 사후 학습 → 블로그 기록**이 연결되는 시스템을 만든다. Stock Lab은 연구·판단의 중심, Key Indicator는 세계 변화의 관측 창구로 둔다. 수익 보장이나 특정 자산의 현재 매수 추천이 아니라, 그 판단을 반복해서 검증할 수 있는 시스템의 구현 계획이다.

## 0. 2026-10-11 실행 통제와 단일 우선순위

이 문서는 단순 아이디어 목록이 아니라 실행 순서와 승인 기준의 정본이다. 기존 문서의 “구현 미착수” 표기는 AGI-02의 스키마 적용·읽기 전용 API 슬라이스라는 사실과 충돌하므로 폐기한다. 다만 이 사실은 수집, 전략 승격, 주문 또는 수익성 개선이 완료됐다는 뜻이 아니다.

현재 모든 신규 구현·수집·데이터 정정·재시작·외부 발송·주문은 동결한다. 계획상의 첫 P0는 다음 한 항목으로 고정한다: **전략 연구 화면과 승격 경로가 존재하는 canonical `strategy_feature_snapshot`, `backtest_run_specs`, 당시 공개 가능 시점(PIT)을 실제로 대조하지 않은 정적 요약 수익률을 매수·전략 승격 근거로 사용하지 못하게 하는 읽기 전용 검증 계약**. 존재하지 않는 테이블, 오래된 정적 산출물, 입력·코드·설정 해시 부재, PIT 증명 불가 중 하나라도 있으면 결과는 `not_usable`이며 순위·수익률은 추천 근거로 노출하지 않는다.

이 P0는 아래 네 단계 외의 방식으로 진행하지 않는다.

1. **Planning & System Verification (Planner)** — 라이브 CWD·PG primary·서빙 API·canonical 테이블/행수/최대 기준일·정적 산출물의 파일 해시와 생성 시각을 읽기 전용으로 확정하고, 정확한 대조표·fail-closed 응답·수용 시험을 발행한다.
2. **Code Generation (Code Doer)** — 승인된 한 수직 슬라이스만 구현한다. DB 쓰기, 스키마 변경, 전략 파라미터 변경, 수집, 재시작은 금지하며 테스트는 먼저 추가한다.
3. **Zero-Defect Confirmation (Checker)** — 구현자와 분리된 환경에서 API 응답·PG read-only 대조·PIT 음성 사례·회귀 시험을 재현한다. 하나라도 미확인이면 `blocked`다.
4. **Evaluation & Final Approval (Planner)** — 1~3의 증거, 실제 serving process, 변경 범위와 자동 발효 여부를 다시 확인한다. 승인 전에는 수익률 수치·전략 순위·매수/승격 신호로 사용하지 않는다.

후속 AGI-03~17, 자동 운용, 기존 미커밋 AGI/가상매매 확장은 이 P0의 최종 승인과 별도 계획·수용기준이 있기 전에는 시작하지 않는다. AGI-02의 이미 적용된 스키마/코드는 `Open_Items_AGI.md`의 사실 기록으로만 유지하며, 그 자체로 기능 완료나 운영 승인으로 표시하지 않는다.

## 5. 원문 보관·수집 설계

### 5.1 수집 범위와 완전성

목표는 owner가 지정한 관심 블로그와 텔레그램 소스의 **접근 가능한 전체 과거 글 + 지속적인 신규·수정 글**이다. 계정에 있는 채널·그룹·개인 대화는 먼저 목록과 포함 범위를 정리한다. 개인 대화는 기본 제외 제안이며 최종 범위는 D02에서 확정한다. 기존 활성 채널을 초기 후보로 가져오되 자동으로 모든 대화에 범위를 넓히지 않는다.

- 소스마다 요청 시작일, 실제 가장 오래된 글, 마지막 수집, 페이지 커서, 목록 건수, 저장 건수, 삭제·권한없음·누락 사유를 기록한다.
- 최근 90일을 먼저 활용하고 과거 전체 백필을 별도 저우선순위 큐로 진행한다. 90일에서 수집을 끝내는 설계가 아니다.
- 신규 수집은 15~60분 주기부터 부하·소스 제한에 맞춰 조정한다. 기존 배치와 중복 실행하지 않는다.
- 메시지 ID 간격을 누락 건수로 단정하지 않는다. 원천 목록이 없으면 완전성은 ‘분모 미확인’으로 표시한다. 접근할 수 없는 삭제·비공개 과거 글은 복구를 보장하지 않는다.
- 동일 소스·외부 ID·본문 해시는 멱등 처리한다. 본문 수정은 새 revision, 삭제 감지는 tombstone으로 기록하며 원문 보존/삭제 정책에 따른다. 권한 오류를 삭제로 오판하지 않는다.
- 조회수·반응 수는 문서 본문 revision과 분리된 시계열로 저장한다.

텔레그램 과거 이력은 사용자 인증이 필요한 `messages.getHistory`와 기존 Telethon 경로를 검토한다. 봇만으로 개인 계정의 모든 과거 기록을 얻는다고 가정하지 않는다. [Telegram 공식 명세](https://core.telegram.org/method/messages.getHistory)

네이버 검색 API는 검색 결과를 반환하며 전체 블로그 원문 아카이브를 보장하지 않는다. 검색은 발견용으로 쓰고 실제 원문 수집은 허용된 피드·원문 접근·내보내기를 소스별 검증한다. [네이버 블로그 검색 API](https://developers.naver.com/docs/serviceapi/search/blog/blog.md)

### 5.2 NVME 저장 구조 제안

새 연구 원문은 `/Volumes/Realtek_NVME/stock_dashboard/research_archive/` 아래 `raw/<source>/<year>/<month>/<document_id>/<revision>/`, `parsed/`, `exports/`, `manifests/`로 분리한다. 이는 제안 경로이며 이번에는 생성하지 않았다. 기존 `reports/`, `telegram_media/`, `postgresql16/`, `stock.db`, `logs/`, `browser_profiles/`, `antigravity_workspace/venv/`는 삭제·이동하지 않는다. 기존 첨부는 위치를 참조해 불필요한 복제를 줄인다.

원문 HTML/JSON/PDF/이미지, 추출 텍스트, 파일 해시, 수집시각을 보존한다. 원문과 메타데이터는 복구 대상이며 임베딩·요약 캐시는 재생성 대상으로 구분한다. 동일 SSD 안의 사본은 장애 대비 백업으로 보지 않는다. 별도 디스크 또는 암호화 원격 백업의 대상·보관 기간을 D07에서 확정한다.

단어 빈도, 대중의 반응, 투자 가치의 세 개념을 나눠 측정한다.

| 지표 | 정의·비교 기준 | 주의점 |

출력은 ‘많이 언급된 주식’ 외에 **실적 개선 대비 관심 부족**, **관심 폭증 대비 실적 근거 부족**, **소수의 독립 출처에서 먼저 나타나는 변화**를 보여 준다. 관심도만으로 매수 점수나 비중을 올리지 않는다. source coverage가 떨어지면 방향성 신호도 품질 경고와 함께 보류한다.

## 7. 블로그 작업과 외부 게시

Stock Lab에서 검토한 연구·실험·기업 업데이트를 선택해 초안을 만든다. 기본 템플릿은 질문, 기준일, 관측 사실, 해석과 가설, 근거 차트, 반대 근거, 다음 확인 항목, 출처다. 투자 결정 결과를 나중에 덧붙일 수 있도록 연구 ID와 게시 ID를 연결한다.

초안 상태는 `draft → evidence_checked → owner_reviewed → published → corrected`로 관리한다. 수정은 과거 내용을 지우지 않고 정정 이유·변경 버전을 남긴다. 숫자는 구조화된 검증값으로 채우고 출처 없는 수치는 생성하지 않는다. 외국계 보고서는 원문 문단·번역·요약을 따로 보존한다. 원문 전체나 비공개 자료가 공개 초안에 섞이지 않도록 공개 가능 근거만 선택한다.

초기 전달 방식은 **네이버 편집기에 붙여 넣을 글·차트·출처 묶음과 미리보기**다. 확인한 네이버 공식 API 목록에 블로그 글쓰기 항목이 없어 자동 게시 API를 전제로 일정을 약속하지 않는다. 게시 연동은 사용 가능한 정식 경로를 별도 검증하고 owner가 게시를 요청한 시점에 연결한다. [네이버 공식 API 목록](https://developers.naver.com/products/intro/plan/plan.md)

개인 연구의 가설과 확인된 사실을 글에서도 구분한다. 게시 후 URL·게시시각·초안 해시를 저장하고, 가능한 방문·반응 통계는 연구 내용과 별도로 분석한다. 게시가 많이 읽혔다는 이유만으로 전략의 신뢰도를 올리지 않는다.

## 8. 기업 상세보고서의 지속 업데이트

기업당 한 번 생성하는 글이 아니라 **기준일별 연구 기록**을 유지한다.

1. 기업 개요: 사업모델, 밸류체인, 제품·고객·지역별 노출, 경쟁사.
2. 숫자: 매출·영업이익·순이익·현금흐름·재고·CapEx·D&A·수주·부문 실적. CFS/OFS·단위·통화·기간·검증 상태를 붙인다.
3. 성장성: 규모·이익률·이익의 반복성·현금전환·수요와 공급능력. 적자→흑자 전환은 단순 성장률 대신 절대 변화와 흑자전환으로 표현한다.
4. 투자 가설: 왜 지금 관찰하는지, 촉매, 예상 확인 시점, 아직 가격/관심에 반영되지 않았다는 근거.
5. 리스크·반증: 유동성·차입·희석·고객집중·경쟁·회계 품질과 가설을 폐기할 조건.
6. 비교: 동종업계, 자기 과거, 가격과 실적의 괴리, 가치 평가의 가정.
7. 변경 기록: 이전 대비 달라진 사실·해석·확신 수준과 그 원문.

새 공시·실적·주요 보고서·거시 노출 이벤트에 영향 섹션만 갱신하고, 매일 누락·신선도를 점검하며 주간 종합본을 만든다. 가격만 바뀐 날은 가격/평가 부분만 갱신한다. 내용이 같으면 새 보고서 버전을 남발하지 않는다.

보고서 버전에는 `as_of`, 생성시각, 사용 fact/document revision, 데이터 스냅샷, 모델/프롬프트 버전, 미확인 필드가 포함된다. 검증된 재무값과 보고서의 전망 수치는 서로 다른 유형이다. 새 자료와 충돌하면 기존 주장을 덮기보다 `conflicting`으로 표시한다. 원천이 정정되면 영향받은 보고서·실험을 찾아 재생성 대기 및 ‘이전 자료 기준’ 상태로 바꾼다.

### 9.2 전략 후보

- A 회복 선행: 현재 실적은 부진하지만 수주·가동률·재고 정상화·마진·현금흐름 등의 선행 개선 증거가 있는 기업. 적자 장기화·자금조달·희석을 별도로 평가한다.
- B 미발견 성장: 이익의 질·규모가 개선되지만 독립 출처 관심·시장 반응이 제한된 기업. 단순 비인기를 저평가로 간주하지 않고 가격·가치·유동성 근거를 확인한다.
- C 추세 확인: 기존 검증 체계의 추세 전략을 조건부 조합 후보로 사용한다. A/B와의 상관관계·하락기 손실·회전비용을 검증한다.

이는 구현할 연구 가설이며 지금 채택된 실거래 전략이 아니다. 국면에 따라 후보 중 2~3개를 선택하되 자격을 갖춘 전략이 부족하면 수를 억지로 채우지 않고 현금 선택을 허용한다.

투자 원칙은 `원문 → 해석 → 측정지표 → 실험 → 결과 → 채택/기각 → 적용 버전`으로 연결한다. 시스템은 개선 제안을 만들 수 있지만 실적 부진을 이유로 owner 원칙이나 운영 임계값을 스스로 바꾸지 않는다. 매매 신호 변경은 SIGNAL_RULES의 검증·승인·변경 이력을 따른다.

## 10. 실적과 가격 비교·OSAT 특화 DB·통계

### 10.1 시점 정합 비교

같은 기업에 대해 실적 개선/악화 × 주가 상승/하락의 4분면을 만든다. 실적은 전년 동기·최근 추세·이익률·현금흐름을 나눠 보고, 주가는 1/3/6/12개월 절대 및 시장·산업 대비 수익률을 병기한다. 분류 임계값은 실험 파라미터이며 고정 추천 규칙이 아니다.

실적의 결산일과 공개일을 분리한다. 공시 이후 다음 거래 가능한 시점부터 사용할 수 있으며, 과거 검증에는 그 당시 공개된 재무·전망·기업 구분을 쓴다. 최신 재작성값은 현재 기업 조회에는 쓰되 과거 의사결정에 소급하지 않는다. 공시시각이 없거나 당시 버전을 복원할 수 없으면 PIT 부적격으로 표시한다.

가격은 canonical view와 `return_usable`을 따르고 기업행위·잠정 가격·상장폐지·거래정지·상장 전 구간을 처리한다. 현금배당 포함 여부를 명시하고, 배당 근거가 없으면 가격수익률로 표기한다. 실적은 나중에 오른 기업만 고르는 사후 선택을 금지한다.

### 10.2 OSAT 데이터 사전

기업·사업부·기간·출처 단위로 패키징/테스트 비중, 고객/최종수요 노출, 제품군, 고부가 공정 노출, 가동률, 설비 증설, CapEx·D&A, 고정비 구조, 수주/리드타임, 수익성, 현금전환을 관리한다. 공시된 사실과 시장 추정을 분리하고 미공개 값은 NULL로 둔다.

`metric_definition`, 단위, 회계 범위, 공개일, 유효기간, 비교 가능성 플래그를 함께 저장한다. 서로 다른 ‘가동률’ 정의를 그대로 평균내지 않는다. 한 기업이 여러 밸류체인 역할을 가지는 다대다 관계를 허용한다. 초기에는 owner 관심 기업 5~10개를 제안하되 실제 대상은 D03에서 정한다.

### 10.3 통계에서 연구 기록으로

팩터 분위별 사후 초과수익, 관심도/실적 괴리 그룹의 결과, 업종별 반응 지연, 국면별 전략 성과를 기록한다. 관측 기간·표본 수·결측 제외 수·분모·비용·신뢰구간을 출력한다. 작은 표본은 미확정으로 남기고, 상관관계를 인과로 표현하지 않는다. 가설을 세운 날짜와 예측 기간을 고정하고 20/60/120거래일 등 사전 정의된 시점에 복기한다.

| 산업 | 반도체 가격·수출·수주·재고·설비투자 | 기업 가설의 선행 근거 |
| 정치·정책 | 선거·제재·관세·수출규제·분쟁·법안 단계 | 국가·고객·공급망 노출과 시나리오 |

먼저 기존 지표를 조사해 유지·보완·신규로 구분한다. 신규는 전략 가설에 연결되고 데이터 이용 가능성을 확인한 것부터 추가한다. 국가·시계열 코드·단위·빈도·계절조정·발표 일정·개정 여부·예상치 공급자를 지표 사전에 기록한다.

값 수준, 전월/전년 변화, 변화 속도, 역사적 분위, 예상 대비 차이를 구분한다. 예상치가 없으면 서프라이즈를 만들지 않는다. 국가별 발표 시간·거래일·휴일을 적용하고 저빈도 지표를 일별로 복제해 표본 수를 부풀리지 않는다. 미발표·지연·수집 실패·실제 불변을 구별한다.

FRED/ALFRED처럼 당시 알려진 값의 조회를 지원하는 원천은 빈티지를 보존한다. 오늘 내려받은 과거 데이터는 당시 값과 다를 수 있으므로 과거 신호 재현에 최신값만 쓰지 않는다. [FRED real-time periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)

### 11.2 이벤트에서 신호까지

`발표/사건 → 확인된 사실 → 전달 경로 → 영향 자산/기업 → 반대 시나리오 → 검증할 전략`으로 연결한다. 예컨대 금리 상승은 성장 기대 상승인지 물가/신용 위험인지 나눠야 하며, 일률적인 매도 트리거로 만들지 않는다. 뉴스의 단일 주장을 정책 확정으로 보지 않고 제안·발표·시행 상태와 공식 근거를 보존한다.

뉴스·블로그·LLM 결과는 우선 연구 입력이다. 전략 실험으로 증분 효과를 검증한 신호만 버전이 고정된 피처로 승격한다. 같은 거시 변화가 종목 점수와 자산배분에서 중복 반영되는지도 추적한다. 종목 진입/매도 공통 판정은 `trend_rules.py`, 전략 선택·자산배분은 별도 계층으로 두고 경계 계약을 명시한다.

### 11.3 외국계 애널리스트 보고서

owner가 접근 권한을 가진 보고서·공개 리서치를 수집한다. 기관·작성자·발행일·대상 기간·기준 통화·추정치·목표가·가정·상향/하향 변경·반대 근거를 추출한다. 번역문은 원문 페이지·문단으로 돌아갈 수 있어야 한다. 과거 전망을 덮지 않고 전망 변경 폭·빈도·실제 결과를 추적한다.

자료의 이용 조건에 따라 원문 보관·외부 모델 전송·공개 요약 권한을 각각 관리한다. 보고서의 주장 수치가 실제 재무값을 덮어쓰지 않도록 `forecast`와 `reported_fact`를 분리한다. 기관별 예측력은 표본 수·기간을 함께 표시하고 자동 권위 점수로 단정하지 않는다.

## 12. 글로벌 투자 기회 발굴

대상은 국내외 주식뿐 아니라 국가별 채권·통화·ETF 등으로 확장하되 실제 거래 가능한 상품과 분석상 자산을 구분한다. 초기 후보 생성은 지표 변화, 전망 수정, 역사 대비 괴리, 산업 전환, 관심도 대비 실적 개선의 규칙 기반 탐지로 시작한다. 이후 변화점 탐지·통계 모델을 기존 탐지 대비 효과가 있을 때 추가한다.

기회 카드에는 다음을 필수로 넣는다: 자산/국가·기준일, 무엇이 변했는지, 왜 지금인지, 직접 근거 2개 이상 또는 단일 근거 경고, 반대 근거, 촉매·기간, 가격 반영 여부의 근거, 실패 조건, 다음 확인 일정, 데이터 공백, 현재 상태(`watch/research/paper/closed`). 같은 원문을 전달한 두 글은 독립 근거 두 개가 아니다.

브라질·일본 채권은 **분석 템플릿 예시**로 둔다. 특정 만기·통화·상품의 현지 수익률, 금리 곡선·듀레이션·볼록성, 물가·정책, 환율, 헤지 비용, 신용·유동성, 세금·수수료와 거래 접근성을 비교한다. 수익률 숫자 하나로 기회를 판정하지 않는다.

원화 기준 총수익은 환율을 ‘현지통화 1단위당 원화’로 정의해 `(1+현지통화 총수익)×(1+환율수익)-1`로 계산하고, 현금흐름 시점·비용·세금·헤지는 별도 모델에 반영한다. 금리 ±100bp, 환율 ±10% 등의 예시 충격은 예측이 아닌 민감도 시나리오다. 실제 세후 결과는 상품·계좌·시점별 규칙 확인 후 계산한다.

글로벌 기회는 기존 DB·과거 연구에서 유사 사례와 실패 사례를 함께 검색한다. ‘AI가 발견했다’보다 새 사실·과거 대비 변화·반증·추적 성과를 보여 준다. 근거가 부족하면 추천 수를 채우지 않고 관찰 대상으로 남긴다.

## 13. 전략 검증·자동 주식/현금 비중·실행

### 13.1 공통 검증 계약

모든 실험은 가설, 피처 버전, 학습/검증/최종 평가 구간, 당시 공개 데이터, 시점별 유니버스, 거래 가능 시점, 수수료·세금·슬리피지·거래량 제약, 재실행 해시를 남긴다. 순차 전진 검증과 분리된 최종 평가 구간을 사용하고, 겹치는 예측 기간은 누수 방지 간격을 둔다. 상장폐지 포함, 재작성값·미래 관심도·나중에 추가된 출처의 소급 사용을 막는다.

비교군은 기존 동일 조건 전략, 고정 주식/현금 비중, 단순 리밸런싱이다. 거시·관심도 피처를 하나씩 뺀 결과와 비교해 실제 추가 효과를 측정한다. 다중 실험 수와 기각 결과도 기록한다. 평균 수익뿐 아니라 최대낙폭, 최악 기간, 회복 기간, 하방 손실, 회전율, 거래 수, 비용 민감도, 전략 간 상관·종목 중복을 본다. 기준선이 잘못됐거나 표본이 부족하면 승격하지 않는다.

### 13.2 비중 결정 구조

`계좌 순자산/현금 → 승인된 위험 한도 → 데이터 품질 → 시장 국면 → 적격 전략 2~3개 → 전략·종목 한도 → 목표 비중 → 현재 비중 차이 → 주문 계획` 순으로 계산한다. 비중 합은 현금을 포함해 100%가 되어야 하며 가용 현금·미체결·결제 예정액을 반영한다. 여러 전략이 같은 종목을 원하면 통합 한도를 먼저 적용하고 전략별 가상 지분을 기록한다.

D04에서 투자 기간, 최대 허용 낙폭·손실, 최소 현금, 종목/산업/국가/통화 한도, 레버리지 허용 여부를 정한다. 확정 전에는 실험용 파라미터만 사용한다. 초기 설계 기본은 레버리지·공매도 없이 시작하는 안이다. 국면 변경에 히스테리시스·최소 유지 기간·리밸런싱 차이 기준을 두어 잦은 매매를 줄이며 수치는 검증으로 정한다.

종목 매도 신호와 포트폴리오 위험 한도에 따른 축소 주문을 별도 사유로 기록한다. 거시 점수가 공통 매도 신호를 몰래 바꾸지 않도록 한다. LLM은 설명을 작성하고, 목표 비중·주문 금액은 버전이 고정된 코드로 계산한다.

### 13.3 자동화 승격

| 단계 | 자동화 범위 | 통과 조건 |
|---|---|---|
| L0 연구 | 지표·보고서·실험 생성 | 출처·수치·시점·권한 검증 |
| L1 그림자 운용 | 목표 비중과 주문 계획만 기록 | 동일 입력 재현, 한도·중복 종목·비정상 데이터 사례 통과 |
| L2 모의 운용 | 가상 주문·체결·비용·대사 | 최소 8~12주 관찰 제안 + 거래 수/위험 이벤트 충분성; 기간 경과만으로 승격 금지 |
| L3 제한 실거래 | 확정된 계좌·소액·한도 내 실행 | D04/D05 확정, 사전 대사·장애 복구·정지 훈련·사용자 운영 전환 승인 |
| L4 완전 자동 운용 | 비중 산출→주문→체결→대사 자동 | L3 검증, 변경관리·정지/복구·상시 위험 제한 유지 |

주문에는 멱등키, 주문 상태 전이, 부분체결/취소 처리, 재시도 전 증권사 주문 조회, 체결·잔고 대사, 일일 주문액/손실 한도, 단일 실행자 잠금, 수동 정지 스위치가 필요하다. 재시작 직후 미체결을 재조회하기 전 새 주문을 보내지 않는다. 리서치 서비스에는 주문 자격증명을 주지 않는다.

품질 저하·원천 지연 시 신규 위험 증가를 차단하고 마지막 목표 비중을 참고용으로 표시한다. 데이터 오류 때문에 전량 매도하지 않는다. 기존 포지션의 비상 축소는 사전 확정된 위험 정책과 신뢰 가능한 별도 가격·계좌 확인이 있을 때만 실행한다. 복구 후 자동 재개 여부도 D05에 포함한다.

## 14. 제안 데이터 모델과 API 계약

아래는 논리 모델이며 DDL 적용 전 기존 스키마와 대조해 확장/신설을 결정한다. 운영 primary 연결은 `connect_primary_db()` 또는 `connect_stock_db()`를 쓴다.

| 논리 테이블군 | 주요 키·필드 | 용도 |

| blog_drafts / publications / alert_outbox | 근거 버전, 검토 상태, 외부 ID, 발송/게시 멱등키 | 출판·알림 감사 |

모든 사실은 ‘대상 기간’, ‘발표 시각’, ‘시스템 최초 인지 시각’, ‘저장 시각’을 구분한다. 역사 연구는 원천의 신뢰 가능한 공개시각을, 실제 전진 재현은 시스템이 인지한 시각까지 반영한다. 발표시각을 입증하지 못하면 수집시각을 보수적 하한으로 쓴다. 저장 시각은 UTC, 화면은 KST 등 선택 지역 시간대로 표기한다.

API 제안: `/api/agi/documents`, `/api/agi/attention`, `/api/agi/companies/{code}/versions`, `/api/agi/theses`, `/api/agi/opportunities`, `/api/agi/blog-drafts`, `/api/agi/allocations`. `/api/research/*`는 이미 `routes/research_lab.py`가 소유하므로 AGI 구현에 재사용하지 않는다. 기존 기업 API와 중복 기능은 공통 서비스로 추출한다. 조회는 부작용 없이 저장된 결과를 반환하고 생성·재생성은 인증된 작업 API가 job_id를 반환한다.

Key Indicator와는 DB 직접 연결보다 `schema_version`, `series_id`, `observation_period`, `released_at`, `vintage`, `value`, `unit`, `quality`, `source_ref`, `watermark`가 있는 인증된 증분 연동을 우선 검토한다. 각 지표의 원천 소유자를 하나로 정하고 한쪽 장애 시 오래된 값 표시·재시도·계약 테스트를 둔다. 외부 저장소 변경은 그 저장소에서 별도로 수행한다.

## 15. API·운영·비용 설계

기존 PostgreSQL·React·FastAPI·스케줄러를 우선 활용한다. 초기에 새로운 메시지 브로커·벡터 DB를 필수로 도입하지 않는다. DB 작업 큐/기존 원장의 처리량을 측정하고 필요할 때 분리한다. 검색은 전문 검색+기업/기간 필터부터 제공하고 Brian_RAG 재사용 가능성과 한국어 검색 품질을 확인한 뒤 하이브리드 검색을 붙인다.

| 연결 후보 | 목적 | 착수 조건·대체 |
|---|---|---|
| 기존 DART/FnGuide/네이버·가격 수집 | 기업 숫자 | 기존 정본·검증 경로 사용; 연구 수집기가 직접 덮어쓰지 않음 |
| Telegram 사용자 API | 과거/신규 원문 | 기존 인증 재사용 가능 여부·범위·rate limit 확인; 실패 지점부터 재개 |
| 블로그 피드/원문·검색 | 발견·아카이브 | 소스별 완전성·이용 조건 검증; 내보내기 파일 대체 가능 |
| FRED/ALFRED, ECOS 및 각국 공식 기관 | 거시·빈티지 | 기존 커넥터와 중복 여부 조사; 코드·단위·개정 이력 계약 |
| 권한 있는 리서치 공급자 | 외국계 보고서·예상치 | 라이선스·보관/전송/게시 범위·가격 확인 전 계약 가정 금지 |
| 모델/OCR API | 추출·번역·요약·근거 검색 | 기존 모델 호환층 우선, 모델별 품질·토큰 비용 측정 |
| 증권사 API | 미래 주문·체결·잔고 | 기존 계좌/주문 기능 감사, L3 전환 조건 충족 |

월 비용은 `신규/수정 문서 수×평균 입력·출력 토큰×단가 + OCR 페이지 비용 + 유료 데이터 구독 + 저장·백업 비용`으로 산정한다. 7일 표본으로 추정하고 호출/토큰/일·월 예산 상한을 설정한다. 동일 원문 해시+추출기/모델/프롬프트 버전은 캐시한다. 예산 소진 시 원문 수집과 품질 점검을 우선하고 비필수 요약을 연기한다. 현재 단가·공급자 계약은 확정하지 않았다.

원문에 포함된 지시문은 데이터로 취급하며 모델의 파일·게시·주문 권한을 바꾸지 못하게 한다. 외부 모델에는 허용된 자료만 전달하고 세션·키는 문서/로그/브라우저에 노출하지 않는다. 일일 수집량, 실패율, 지연, 원문 대비 추출 성공률, 큐 적체, 비용, 디스크 여유, 백업·복원 결과를 관리자에서 확인한다. 재시도는 제한·지수 지연·실패 큐·수동 재처리를 갖춘다.

## 16. 브리핑·알림과 추가 개선

아침 브리핑은 ‘새 사실 → 내 보유/관심 대상 영향 → 근거/반증 → 다음 행동’을 중심으로 작성한다. 주간에는 실험·가설 결과와 owner 판단을 복기한다. 일일 1회 요약과 중대한 가설 훼손/운영 장애만 즉시 알림을 초기안으로 두고 D06에서 전달 채널·시간을 확정한다.

동일 이벤트는 멱등키·쿨다운·중요도 상승 조건으로 중복 발송을 막는다. 알림이 열린 비율보다 실제 검토 도움·불필요 알림·오탐·미탐을 측정한다. 정정된 근거가 이미 발송/게시됐으면 정정 큐를 생성한다.

추가 제안은 다음과 같다.

- **반증 중심 연구**: 각 기회에 ‘이 판단이 틀렸음을 보여 줄 신호’를 반드시 둔다.
- **자료 계보와 정정 전파**: 한 숫자 수정이 어떤 보고서·백테스트·게시글에 영향을 주는지 역추적한다.
- **실패한 실험 보존**: 잘된 사례만 모으는 편향을 막고 비슷한 실패의 반복을 줄인다.
- **데이터 공백 지도**: 가장 많이 수집한 소스보다 투자 판단에 필요한데 빠진 정보부터 보완한다.
- **판단 일지**: 당시 정보·선택·대안·예상 결과를 고정해 결과를 본 뒤 이유를 바꾸지 못하게 한다.
- **공급망 연결**: 기업–제품–고객–국가–정책 관계를 점진적으로 구성한다. 초기에는 관계형 테이블로 충분하며 그래프 DB는 필요성이 입증되면 도입한다.

## 17. 단계별 실행 일정과 의존성

기간은 전담 개발자 1명과 owner 검토를 가정한 순수 구현 노력의 초안이다. 데이터 권한·백필·기존 결함 해결·외부 저장소 연동 대기와 모의운용 관찰 기간은 별도다. 선행 완료 조건을 통과해야 다음 단계로 승격한다.

| 단계 | 노력 추정 | 산출물 | 완료 게이트 |
|---|---|---|---|
| P0 기반 확정 | 3~5일 | 소스/기존 스키마/지표 목록, 기존 품질 이슈 매핑, owner 원칙 v1, 예산·권한 초안 | AGI-00/01/09 설계 검토, 중복 구현·운영 충돌 없음 |
| P1 보관·검색 | 1~2주 | 기존 채널+블로그 소수 시범, 원문 revision, 재개 가능한 백필, 검색·수집 현황 | 중복/수정/권한 오류/재시도/복원 검증 |
| P2 기업·관심도·블로그 | 2~3주 | 기업 5~10개 보고서, OSAT 비교, 관심도, 근거 연결 초안 | 표본 정확성·변경 추적·숫자 출처·초안 품질 확인 |
| P3 거시·글로벌 기회 | 2~3주 | 지표 사전·빈티지·Key Indicator 계약, 외국계 보고서·기회 카드·알림 | 정정·발표 지연·수집 실패·영향 연결 검증 |
| P4 전략·비중 그림자 운용 | 2~3주 | A/B/C 실험, 국면별 조합, 목표 비중과 비교군 | 시점 누수/비용/생존 편향 점검, 기존 품질 선행 조건 통과 |
| P5 모의→제한→완전 자동 | 구현 2~4주 + 관찰 | 주문·체결·대사·중단/복구, 운영 계약 | 최소 8~12주 모의 제안과 충분한 표본, D04/D05 및 전환 승인 |

**첫 사용 가능한 MVP는 P0~P2**, 즉 전담 기준 약 4~6주 추정이다. 기존 수집 연결 재사용으로 줄어들 수 있고 권한·원문 품질에 따라 늘어난다. 전 기능 구현 노력은 약 10~16주, 실거래 승격 일정은 별도로 정한다. 백필 완료를 기다리지 않고 확보된 범위를 표시해 연구 기능을 먼저 사용한다.

과거의 “첫 실행 묶음”은 AGI-00/01/09 및 AGI-02였고, 이력은 `Open_Items_AGI.md`에 사실대로 남긴다. **현재 다음 실행 묶음은 AGI 확장이 아니라 §0의 전략 연구 증거 정합 P0 단일 수직 슬라이스**다. 순서는 (1) Planner의 라이브 read-only 대조표와 수용기준 확정, (2) Code Doer의 fail-closed 표시 구현, (3) Checker의 독립 API·PG·PIT 재현, (4) Planner 최종 승인이다. 이 승인이 끝나기 전에는 AGI-03/04/06, 수집 범위 확대, 블로그 발행, 전략·비중·자동운용 작업을 시작하지 않는다.

## 18. 검증·완료 기준

아래 수치들은 초기 제안 기준이며 기존 성능 측정값이 아니다. 업무 중요도·표본 결과에 따라 구현 전 확정한다.

| 항목 | 검증 방법·통과 조건 |
|---|---|
| 수집 완전성 | 조회 가능한 원천 목록과 저장 ID 전수 대조, 설명 없는 누락 0; 분모 불명은 완전 수집 표시 금지 |
| 멱등/수정 | 같은 배치 3회 재실행 중복 0, 수정 글 revision 1개 추가, 커서 중단 후 재개 결과 동일 |
| 기업 식별 | 소스·언어별 층화 표본 최소 200건, 정확 매칭 정밀도 98% 이상 제안, 재현율·모호 판정 비율 병기 |
| 주장 추출 | 최소 100개 주장에 원문 위치·시각·종류 검토, 지원되지 않는 사실 주장 0; 범위 밖 자동 일반화 금지 |
| 수치/보고서 | 시범 기업 5~10개에서 표시된 핵심 수치 전수 원천 대조, 비교 건수와 미확정 수 공개; 숫자 정본 기준 준수 |
| 갱신 | 새 사실 수집 후 관련 섹션만 갱신, 이전 버전 조회·차이·근거 클릭 가능, 변경 없는 재생성 중복 0 |
| 거시/Key Indicator | 단위·빈도·빈티지·시간대·지연·개정 샘플 계약 테스트, 미확정 데이터는 신호 승격 차단 |
| 전략 | 데이터/코드/설정 해시로 재현, 누수 사례 테스트, 비교군·비용·최악 구간·표본 수·기각 실험 보고 |
| 비중·주문 | 합계/현금/집중 한도 준수, 중복 주문 0, 부분체결·재시작·API 타임아웃·잔고 차이·정지 훈련 통과 |
| 공개/권한 | 개인 자료의 비인증 노출 0, 검토되지 않은 초안 자동 게시 0, 외부 문서 지시문이 권한을 바꾸지 못함 |
| 운영 | 잡 실패가 success로 숨지 않음, 비용 상한 작동, 원문·DB를 별도 백업에서 표본 복원 |

완료 보고는 산출물·비교 건수·실행 ID·남은 한계를 함께 남긴다. 모델 자체 점수나 결측을 제외한 높은 비율만으로 ‘검증 완료’라고 하지 않는다. 문서·스키마 검토 완료와 운영 기능 완료를 구분한다.
