# 안티그래비티 에이전트 핵심 개발 수칙 (Rules)

## 1. 역할 분리의 원칙 (Separation of Concerns)
* 웹 크롤링 및 메신저 전송 로직 구현 금지. 이는 외부 OpenClaw의 역할임. 백엔드는 API 통신, DB 연산, 차트 데이터 포맷팅에만 집중한다.

## 2. 시계열 데이터(주가/차트) 처리 최적화 (중요)
* 주가 데이터(OHLCV)는 분기별 재무 데이터보다 훨씬 방대하므로, SQLite DB Insert 시 단건 처리가 아닌 일괄 처리(Bulk Insert) 방식을 사용하여 성능 저하를 막을 것.
* 프론트엔드로 차트 데이터를 반환할 때는 불필요한 데이터를 덜어내고, 차트 라이브러리(Recharts 등)가 바로 소비할 수 있는 Key-Value 쌍 배열 형태로 경량화하여 응답할 것.

## 3. macOS 환경 최적화
* 파일 시스템 경로 지정 시 macOS(UNIX) 환경에 맞출 것. 백그라운드 실행을 위한 안정성 확보.

## 4. 강력한 API 에러 핸들링 및 로깅
* OpenClaw가 방대한 주가 배열 데이터를 보낼 때 누락된 값(NaN/Null)이 있더라도 DB 에러가 나지 않도록 Pydantic 모델에서 기본값(Default) 및 유효성 검사를 철저히 할 것.
* 주요 에러는 `logging`으로 남길 것.

## 5. 단계별 검증 (Step-by-Step Validation)
* 각 Phase 완료 시 반드시 더미 주가/재무 데이터를 API로 쏘아보고 DB 적재 및 JSON 반환이 정상 작동하는지 확인 후 다음 Phase로 넘어가라.

## 6. 데이터베이스 설계 원칙 (Database Schema Rules)
* 하드코딩 사용은 최소화로 할것. 하드코딩 사용시 꼭 위치 및 수정 가능한 정보를 남겨서 수정가능하도록 할것.

## 7. 언어 및 주석 원칙
* AI 분석 결과, 모든 코드 주석, 변수명(가능한 경우), 및 공식 문서는 한글로 작성하여 가독성을 높인다.
