  - `telegram_channels.id=13`

## 2. 이 프로젝트에 이미 있던 것 vs 새로 만든 것

체리형부 채널을 읽기 전부터, 이 프로젝트의 `routes/tenbagger.py` `turnaround-watch`는
**이미 독립적으로 거의 같은 결론에 도달해 있었다**(2026-07-19~28 세션, 에이엘티
사례를 직접 분석하며 재도전/이익의질/희석위험 신호를 walk-forward 검증). 즉 3대
스크리닝의 ①(적자후흑자전환)은 이미 매우 정교하게 구현되어 있었다:

- 확정 흑자전환(A) / 단일분기 흑자전환(C) / 재도전 이력(D) / 감가상각주도 이익의질(E)
  / 희석위험(CB·BW·EB) / 꿈촉매(특허·기술이전) — 전부 walk-forward 검증 완료, 실전 서빙 중.

**이번에 새로 추가한 것** (`routes/cherry_screener.py`):

1. **②매출 역대최대 스크리닝** — 없던 신호. 당분기 매출을 전체 분기 이력 최고치와 직접 비교.
2. **③주가 미반영(가치평가 갭) 스크리닝** — 없던 신호. 시총-순현금=사업가치, 업종 내
   ex-cash PSR 중위값과 상대 비교(같은 sector_large 내 5종목+ 표본에서만 산출).
3. **선행지표 상관계수(계약부채 vs 차분기매출)** — `contract_advance_signals`(Codex
   구축) 데이터를 실제 상관분석에 처음 활용(기존엔 signal_score만 참고정보로 노출).
4. **기관 매집 신호** — `dart_major_holders`(5%룰 대량보유)를 처음으로 스크리닝에 활용.
5. **①~③ 통합 스코어(0~3점)** — 3개 스크리닝을 하나의 랭킹으로 결합.

**의도적으로 자동화하지 않은 것** (정성적 해석이 필요하거나 종목마다 참조 지표가
달라 전종목 공통 로직화가 불가능):

- 사이클 포지셔닝(업스트림 지표 연동) — 반도체는 `quant_major_indicator`의
  `DRAM_SPOT` 계열을 수동 대조해야 함, 다른 업종은 참조 지표 자체가 다름.
- P×Q 분해, 재고 세부항목 상관 — 종목별 재고구조 해석이 필요, 전종목 배치화 시
  거짓 신호가 다수 발생할 위험(예: 서비스업은 재고 개념 자체가 없음).
- 비용의 성격별 분류→손익환원식 — `cost_structure`/`cost_breakdown` 테이블은
  있으나 손익분기 공식 도출은 종목별 사업구조 이해가 선행되어야 함.
- 오버행/락업 스케줄 — 상장일/보호예수 해제일 데이터 자체가 이 프로젝트에 없음
  (신규 수집 필요, 별도 과제).
- 반론(약세논거) 서술, 판정 changelog — 자연어 생성/해석 영역, 스크리너의 역할이
  아니라 turnaround-watch 상세보기 등 후속 분석 단계의 몫으로 남김.

### 데이터 품질 이슈 — 근본원인 규명 및 수정 완료 (2026-08-09 추가조치)

`financial_data.cash` 필드에서 **2,484종목·16,730행이 음수값**을 가지고 있음을
발견(예: 에이엘티 172670 CFS 2026Q1 cash=-311,804,881원). 사용자 지시("근본 원인을
수정하고 고쳐야해")에 따라 DART 원문을 직접 재조회해 원인을 확정했다.

**근본원인**: DART 현금흐름표의 "현금및현금성자산의순증가(감소)"(기간 중 증감액,
계정id `ifrs-full_IncreaseDecreaseInCashAndCashEquivalents`)는 정의상 음수가
정상이다. 이 계정id가 `collectors/dart_mapping_engine.py`의 매핑테이블에 없어
`collectors/dart_collector.py`의 키워드 폴백으로 낙하하는데, account_nm에
"현금및현금성자산"이 포함돼 `cash` 키워드와 오매칭됐다. `revenue`/`total_assets`
등은 이미 "해당 재무제표(손익계산서/재무상태표) 행만 허용" 방어가 있었으나
**`cash`만 이 방어가 빠져있어** 재무상태표의 실제 현금잔액(항상 0 이상)이 현금흐름표의
증감액(음수 가능)과 혼동될 수 있었다. 대부분은 "이미 값이 세팅되면 덮어쓰지 않음"
보호로 걸러졌지만, 재무상태표 행 자체가 없거나 해당 회차에 매핑 실패한 케이스에서
음수 증감액이 그대로 저장된 것으로 확인(에이엘티 172670 2026Q1·2025Q3 등 실측
재현 완료).

**수정 완료**:
1. `collectors/dart_collector.py` `_parse_fin_df()` — `cash`를 `total_assets` 등과
   동일하게 "재무상태표(BS) 행만 허용"하는 sj_nm 필터에 추가(account_id 매핑 경로,
   키워드 폴백 경로 양쪽 모두). 재무상태표 행이 아예 없는 취약 케이스로 직접
   시뮬레이션해 방어 확인 완료.
2. `scripts/backfill_negative_cash_20260809.py` 신규 — 오염된 16,730행을 수정된
   파서로 DART 재조회해 백필(`RotatingOpenDartReader` 3키 로테이션 재사용).
   10건 dry-run 검증 후 전체 백그라운드 실행 시작(예상 2~3시간, 진행 로그
   `scratch/backfill_negative_cash_20260809.log`).

`routes/cherry_screener.py`의 방어 로직(CFS/OFS 중 0 이상인 값만 채택)은 수정 이후
수집분에는 더 이상 필요 없지만, 전환기간 안전장치로 유지.
