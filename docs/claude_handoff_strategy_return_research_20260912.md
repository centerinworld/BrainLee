## 1. 작업 목표와 범위

현재 전략센터의 주식 매수·매도 전략을 최신 데이터, 추가 시그널, 무결성 수정 기준으로 다시 연구하라. 과거 기각된 데이터와 전략도 포함한다. 목적은 **동일 자본·동일 기간·동일 체결 조건에서 현재 기준선보다 비용 차감 수익률이 높고, 개선 원인을 설명할 수 있는 후보를 찾는 것**이다.

이번 문서는 실행 지시서다. Codex는 저장소 문서와 코드를 읽었으며 백테스트, 운영 DB 재감사, 수집, 전략 변경은 실행하지 않았다. 아래 수치는 과거 기록이며 오늘 검증한 결과가 아니다. 개선안은 검증할 가설이지 수익 개선이 확인된 처방이 아니다.

Claude는 기준선 재현 → 기각 원장 복원 → 데이터 변화 확인 → 매수·매도·배분 실험 → 검증 보고서까지 수행한다. 성과가 개선되지 않으면 그 사실과 근거를 남긴다. 연구 스크립트·격리된 결과물을 만들되, 연구만으로 운영 기본값·자동매매·자본 배분을 변경하지 않는다.

**후속 감사가 앞선 PASS를 대체할 수 있다.** 9/9 가격 게이트 강화 후 선택 전략 26개 모두 오염 보유기간이 발견됐다는 기록이 있고, 9/11 일부 복구 후에도 실패가 남았다. 이는 특정 시점 선택 전략 집합의 감사 결과이며 위 병합계좌 각각의 오늘 상태를 직접 증명하지 않는다. 구성 런과 병합 런 모두 최신 입력 지문으로 상태를 재조회하라.

9/11 기록에는 2022년 가격 접합 후보 미해결, 정상 KRX 백필도 쓰기 감시로 격리되어 160만 건 이상 쌓인 상황이 있다. 이 숫자를 현재 확정 오류 건수로 취급하지 말고, 미검증·정상 백필·확정 오류를 구분하라. 무결성 기준을 느슨하게 해 수익률을 회복시키는 접근은 제외한다.

- 두 디렉터리에 동명 파일이 있으나 내용과 시점이 다르다. 시작 시 양쪽 `CLAUDE.md`, 실행 모듈 경로, Git 상태와 실제 DB 연결을 확인하라. 루트의 오래된 코드로 운영 성과를 판정하지 않는다. 코드 수정 경로와 운영 반영 경로는 프로젝트 지침에 맞춰 명시한다.
- 운영 성과 판정 데이터는 PostgreSQL이다. 레거시 `stock.db`를 운영 DB처럼 사용하지 않는다. 옛 스크립트의 `sqlite3` import가 호환 계층을 거치는지 실제 연결을 확인한다.
- 기존 변경이 다수 있으므로 사용자·다른 세션의 작업을 덮어쓰거나 일괄 정리하지 않는다. 연구 백필과 운영 수집을 동시에 무제한 실행하지 않는다.

## 4. 단계 A — 재현과 데이터 변화의 효과 분리

1. 전략센터 전체 전략·병합계좌·현재 노출 순위·구성 런·파라미터·거래 원장·검증 상태를 저장한다.
2. 코드 커밋뿐 아니라 미커밋 diff 해시, 데이터 스냅샷/버전, 입력 지문, 수집 완료시각, 공시 가용시점 정책, seed를 기록한다.
3. 기준선 3종을 동일 기간·원금·비용으로 새로 실행한다: sector_focus 단독, sector_focus+v2, composite.
4. 과거 종료일 고정 비교와 기간 연장 비교를 분리한다.
5. 2×2 비교(과거/최신 데이터 × 과거/개선 규칙)로 효과를 분리한다.
6. 거래별 차이를 입력→신호→주문→현금/보유→손익으로 연결한다.
7. 오염 종목 사후 제외 성과는 선택 편향이 있을 수 있으므로 전체시장 검증으로 승격하지 않는다.
